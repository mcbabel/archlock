A lockfile for your architecture. You own the design, your agent writes the code.

Coding agents write code faster than anyone can review it. archlock keeps your modules, their allowed dependencies and their public APIs in small sketch files you own, and fails CI when the code drifts from them.

npx archlock init
Source on GitHub
  • push ↓sketch to code
  • accept ↑code to sketch

One plan, one agent run, three lines to review

The human plans a new module and a changed signature in the sketch. Claude Code writes the code and compiles it, check turns green, and diff shows the reviewer what changed in the architecture.

Two directions, like a snapshot test

When the code and a sketch disagree, archlock check tells you that and where. You decide which side is right.

archlock accept

code → sketch

This code change is intended. Update the sketch, and keep every comment and invariant written in it.

archlock push

sketch → code

The sketch is the truth. archlock turns every difference into a work order and lets your agent change the code until check is green.

How it works

The demo project from the video, step by step. Every snippet below is real output.

  1. Lock the architecture you have

    init detects your modules and writes one sketch per module: its files, the modules it may import, and its public API with signatures. No model, no network.

    $ npx archlock initFound 10 modules (subdirectories of src/):  api        src/api/**  6 public symbols, 5 dependencies  billing    src/billing/**  14 public symbols, 6 dependencies  cart       src/cart/**  13 public symbols, 3 dependencies  …Wrote archlock.config.json, 10 sketches and README.md in archlock/   751 lines of code → 253 lines of architecture (3.0×)

  2. Plan the change in the sketch

    Change a signature, add a rule, or plan a whole module in a new sketch file. check now reports 7 errors: the plan is not implemented yet.

      archlock/billing.arch.py       payment: PaymentRef,- ) -> Promise[Invoice]: ...+     paidAt: Date,+ ) -> Promise[Invoice]:+     # must: use paidAt from the payment provider, not the server clock+     ...  archlock/notifications.arch.py  new module, see below

  3. Let your agent write the code

    push builds a precise work order from every difference, runs your agent headless, checks again, and repeats with what is left. It never commits.

    $ npx archlock push --agent claudearchlock push: round 1/3: claude works on 7 changes…Round 1 took 1m 22s. Checking again… archlock push: 1 round with claude  ✔ done  notifications.Channel: implemented  ✔ done  notifications.invoicePaidMessage: implemented  ✔ done  notifications.Message: implemented  ✔ done  notifications.Notifier: implemented  ✔ done  notifications.OutboxNotifier: implemented  ✔ done  notifications.registerNotifications: implemented  ✔ done  billing.markPaid: signature now matches the sketchThe code matches the sketches. Review the changes (git diff) and commit them.

  4. Fail CI on drift

    check runs in CI and exits with 1 when code and sketches disagree, with the file, the line and both versions. Here it is before the agent ran:

    $ npx archlock checkbilling  ✖ signature_changed  function markPaid differs from the sketch      sketch: async def markPaid(deps: BillingDeps, invoiceId: InvoiceId, payment: PaymentRef, paidAt: Date) -> Promise[Invoice]      code:   async def markPaid(deps: BillingDeps, invoiceId: InvoiceId, payment: PaymentRef) -> Promise[Invoice]      at code src/billing/payments.ts:13 · sketch archlock/billing.arch.py:61…archlock check: 7 errors, 1 note

  5. Review the architecture, not the noise

    diff analyses the code of both commits, so architecture changes show up even if nobody ran accept. The GitHub Action posts it as one comment on the pull request.

    $ npx archlock diffarchlock: 3 architecture changes (compared with main @ ba498e1)~ billing.markPaid  (deps, invoiceId, payment) → (deps, invoiceId, payment, paidAt: Date)+ demo_shop         new dependency: notifications+ notifications     new module (6 public symbols; depends on customers, events, shared)85 lines of code changed → 3 lines of architecture

A sketch, and what reviewers see

Sketches are valid Python syntax whatever your language, so they get highlighting everywhere, and people and LLMs read them easily. Types stay in your language: Promise[void] is TypeScript’s Promise<void>.

85 lines of code changed → 3 lines of architecture

Hard contract (checked, can fail CI): modules, allowed dependencies, public symbols with their kind and signature. Soft contract (never fails CI): docstrings and comments like # invariant:, # must:, # never:. The sketch format.

Questions

Does it need an API key?

No. init, check, accept, diff, stats, graph and mcp are deterministic and offline: same input, byte-identical output, no model, no network, no telemetry. Only push (and the optional init --with-summaries) start the coding agent you already use.

Which agents?

push is tested end to end with Claude Code: on the demo it needs one round of one to two minutes, and the agent compiles what it writes. Codex CLI and OpenCode are supported (their flags are checked against their --help) but not yet battle-tested. Any other agent works through a command template, or paste the work order from archlock push --print-prompt. There is also an MCP server (archlock mcp), an agent skill and an AGENTS.md/CLAUDE.md section (archlock init --agents).

Which languages?

TypeScript and JavaScript (.ts .tsx .mts .cts .js .jsx .mjs .cjs, tsconfig paths, pnpm/npm/yarn workspaces), Vue, Svelte and Astro components (.vue .svelte .astro: props and events are the component's signature), Python (src and flat layouts, __all__, dataclasses, Protocols, Enums) Go (one module per package, go.mod module paths, methods, generics, embedding) Rust (Cargo workspaces, crates and top-level modules, pub use re-exports, traits, enums with data) and Java (Maven and Gradle source roots, packages, records, enums, sealed types), also mixed in one repository. More languages are on the roadmap; the extractor interface is small.

What does it not do yet?
  • Extraction is syntactic: without annotations a type is '<inferred>' (4–7% of type positions in Hono, Zod and Flask, 29% in shadcn-svelte with its untyped Svelte 5 state classes). A mode using the TypeScript type checker is planned, not built.
  • Module detection is a starting point: one large package becomes one module until you split it with __paths__.
  • No edges across languages: a TypeScript app calling a Python API over HTTP is not an import.
  • push has only needed one round with a real agent so far; more rounds are tested with a scripted test agent.
  • The full list: known limitations.
How fast is it?

About 2.8 seconds for check on a 93,000-line repository without cache, 1.2 seconds with the file-hash cache. init on Hono takes 0.6 seconds on a desktop PC.

Does it rewrite my code?

Only push changes code, through your agent, and it never commits. It warns about uncommitted changes first, so you can review exactly what the agent did.
