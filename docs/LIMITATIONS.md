# Known limitations

archlock is young. This is the honest list of what it does not do, in three parts: what is not
built yet, what is left out on purpose, and what no static tool can see.

## Not built (yet)

- **Typed extraction is opt-in and TypeScript only.** By default extraction is syntactic: without annotations, types are `'<inferred>'` (4–7% of type positions in Hono, Zod and Flask, 29% in shadcn-svelte with its untyped Svelte 5 state classes; see the [real-world examples](../examples/real-world)). [`"typed": true`](FORMAT.md#mapping-from-typescript) lets the TypeScript checker fill them in for `.ts` and `.js` files; it needs the project's type declarations installed, is slower, and does not cover `.vue`, `.svelte` and `.astro` files or other languages.
- **`push` is tested end to end with Claude Code and OpenCode.** Codex CLI uses flags checked against its `--help`, but has not been run end to end. The OpenCode run (2.1.3, on a planned function in a test fixture) took two rounds: the model provider failed during the first, and `push` re-checked and handed the remaining difference to the second. Claude Code runs on the demo finished in one round; more rounds are covered by tests with a scripted agent.
- **Module detection is a starting point.** One large package (Zod) becomes one big module until you split it with `__paths__` (the Zod example shows this). Python projects without a single top-level package fall back to top-level folders.
- **Component gaps:** a props type defined in another file is a base, not expanded into fields. Not part of the signature: slots and snippets, `defineExpose`, `defineSlots`, Svelte 4 `export const`/`export function` and `export { a as b }` props, `$bindable` (a bindable prop is an ordinary prop), and Astro's `Astro.slots`. Components registered globally with `app.component()` are no dependency of the templates that use them. Vite aliases and a Nuxt `srcDir` are read as text, so computed values are not seen.
- **Rust:** `impl` blocks for types of other crates and blanket impls are ignored; paths are resolved without type information, so an imported name that is both a module and an item can resolve to the module.
- **Java:** dependencies come from imports and qualified names, so a class used through a variable of an unrelated type does not add one; Kotlin, Groovy and Scala sources in the same build are not read; `init` leaves out files whose directory does not match their `package` declaration.
- **C#:** extension methods are matched by name and namespace, not by receiver type, so of two extension methods with the same name in scope the first visible one is the dependency; `.sln` files are not read (projects are found by their `.csproj`).
- **Go:** external modules are named by `require` lines, not resolved, and `vendor/` is not read (vendored packages count as external).
- **Renames that change more than the name** lose their comments: `accept` carries comments over only when a removed and an added symbol are otherwise identical and the pairing is unambiguous, and reports the others as lost; it never drops them silently.
- **Very large types** appear as long quoted strings unless the project opts into [`maxTypeLength`](FORMAT.md#very-long-types-opt-in). Type parameters and bases are never abbreviated, and an abbreviated type cannot be planned through `push` (the agent only sees its hash), so a planned change to it must be written out in full.
- **Cold runs on large repositories** take a few seconds: 2.8 s for `check` on 93,000 lines without cache, 1.2 s with it; 2.1 s without cache for shadcn-svelte (133,000 lines, 2,145 Svelte files); 3.9 s for gitea (329,000 lines of Go, TypeScript and Vue) and 6.3 s for opentelemetry-go (757,000 lines in 423 packages, 1.8 s with cache); 1.9 s for tokio (119,000 lines of Rust); 1.2 s for Apache Commons Lang (99,000 lines of Java); 1.4 s for Newtonsoft.Json (62,000 lines of C#). The cache file is about 14 MB at that size.
- **Windows:** CI is green, but custom `agent.command` templates with complex quoting may behave differently in `cmd.exe`.

## Left out on purpose

These are decisions, explained in [DESIGN.md](DESIGN.md); each would make sketches longer
without telling other modules more about what they may call.

- **Non-public members:** `protected`, `internal`, package-private and unexported members, and Go's unexported struct fields. The sketch is the API other modules can use.
- **Annotations and attributes** (Java, C#), Go struct tags and default parameter values (only whether a parameter has a default is recorded).
- **Trait methods on implementing types** (Rust): `impl Display for User` makes `Display` a base of `User`; the methods are in the trait's sketch.
- **Enum constant arguments and bodies** (Java): constants are compared by name.

## What no static tool sees

- **Code generated at build time:** items generated by Rust macros (other than item-level macro bodies that parse as items) and build scripts, C# source generators and code in `obj/`. Generated files committed to the repository count like any other code.
- **Dynamic exports:** Python's `__getattr__` and `globals()`, computed TypeScript member names, and objects assigned to `module.exports` piece by piece in loops. With conditional definitions (Python), the first one counts.
- **No edges across languages** in mixed repositories: a TypeScript app calling a Python API over HTTP is not an import.
